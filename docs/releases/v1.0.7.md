## What's new

- Added lightweight mode, enabled by default, to prioritize the game while preserving the Cockpit, tyre data, chat, telemetry, race events, strategy and available Spotter features. Change it in System & Devices and restart the app.
- Limited UI telemetry publication to about 10 Hz in lightweight mode and suspended it while the app is hidden/minimized; restoring the window immediately shows the latest sample. Core telemetry/event processing retains its existing cadence.
- Made local speech models load on demand and release their contexts after 60 seconds idle in lightweight mode. STT and local TTS use at most two CPU threads, with low-priority workers; an explicit external OpenMP override remains respected by local TTS. Automatic AI device selection favors CPU, while an explicitly selected Vulkan device is retained.
- Removed repeated deep copies of telemetry/opponent snapshots across the worker/GUI queue and facade, and reduced per-sample session-key and map-key allocations.
- Bounded a push-to-talk capture at 30 seconds, submitting once even if the physical button is released later, while retaining the existing microphone pre-roll.
- Added OpenAI-compatible Speech API TTS under AI & Voice → Other TTS, with configurable endpoint/model/voice, a separate key stored in Windows Credential Manager, streamed PCM playback, pause/resume and retry. Google and local VieNeu remain available.
- Reduced the requested online playback buffer from one second to 200 ms at 24 kHz mono PCM. Provider/network/model time and the audio driver still affect actual latency; this is not an 800 ms latency guarantee.
- Added Windows resource/frametime capture scripts and a repeatable protocol for both Assetto Corsa and Assetto Corsa Competizione.

Lightweight mode trades model residency for a slower first speech request after startup or an idle period. For an 8 GB machine, online TTS and an API/remote LLM avoid keeping additional local models resident. Local STT still uses memory while recognizing speech.

The additional telemetry optimization reduced allocation calls by 37–50% in scoped native Linux replay fixtures with AI/simulator I/O stubbed. Peak RAM was essentially unchanged in those fixtures. These figures are not real-game FPS, whole-app RAM savings or an 8 GB/no-stutter guarantee. Actual AC/ACC sessions and model/network latency still need measurement on the user's Windows hardware.

The Windows package uses an AVX2 CPU baseline. A working Vulkan runtime/driver is still required by the bundled Vulkan build, including when CPU compute is selected. Models, voices and the existing installation/game-setup flow are retained. ACC nearby-car Spotter remains unavailable without the required wheel geometry.

See [performance and TTS guidance](https://github.com/tminh-U/RaceEngineer/blob/v1.0.7/docs/performance.md) and the [Windows AC/ACC measurement protocol](https://github.com/tminh-U/RaceEngineer/blob/v1.0.7/docs/windows-performance-capture.md).
